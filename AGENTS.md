# Agent guidelines

Guidance for AI agents (and humans) working in this repository.

## Commit messages

**All commits must follow [Conventional Commits](https://www.conventionalcommits.org/).**

Format: `<type>[optional scope][!]: <description>`

Common types used here: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`,
`ci`, `perf`. Scope is optional and names the affected area, e.g.
`fix(ci):` or `test(blog):`.

Breaking changes (including renaming or removing a public option, function, or
binding API) MUST be marked with a `!` after the type/scope and a
`BREAKING CHANGE:` footer describing the migration:

```
refactor!: rename entry_points option to input

BREAKING CHANGE: the `entry_points` build option is now `input` across the
core API and every binding (Go `Input`, Node/JS `input`, Python/PHP/Ruby
`input`).
```

Releases are automated from commit history, so the type and breaking-change
markers directly drive version bumps. Get them right.

## Keep the public API in sync across all bindings

The Rust core (`crates/wesc`) is exposed through several language bindings.
When you change a public build option (add, rename, remove, retype), update
**every** surface in the same change:

- Core: `crates/wesc/src/lib.rs` (`BuildOptions`) + `crates/wesc/README.md`
- Go: `crates/wesc-go/include/wesc.h`, `crates/wesc-go/src/lib.rs`,
  `crates/wesc-go/wesc.go`, tests, and README
- Node: `crates/wesc-node/src/lib.rs`, the generated
  `packages/wesc/index.d.ts`, `packages/wesc/bin/cli.js`, and README
- Python: `crates/wesc-py/src/lib.rs`, `crates/wesc-py/python/wesc/__init__.pyi`,
  and README
- PHP: `crates/wesc-php/src/lib.rs`, `crates/wesc-php/stubs/wesc.php`, and README
- Ruby: `crates/wesc-rb/ext/wesc/src/lib.rs`, `crates/wesc-rb/lib/wesc.rb`,
  and README
- Examples under `examples/` that call the bindings

Use a repo-wide search (e.g. `grep`) for the old name to confirm nothing is
left behind, including docs and generated files.

Naming conventions per binding: snake_case in Rust/Python/PHP/Ruby
(`input`), camelCase in the JS/Node API (`input`), PascalCase fields in Go
(`Input`), and matching `wesc.h` C parameters.

## Generated files

- `packages/wesc/index.d.ts` is auto-generated by NAPI-RS. A Prettier
  format-on-save hook may reflow it; keep edits minimal and prefer the
  generator's style.
- `crates/wesc-py/python/wesc/__init__.pyi` and `crates/wesc-php/stubs/wesc.php`
  are hand-maintained stubs that must mirror the Rust signatures.

## Validation

This is an npm-workspaces monorepo. From the repo root:

```sh
npm install          # installs every workspace
npm test             # runs each package's tests
npm run lint         # lints each package
npm run build        # builds each package
npm run build:native # builds the native Node addon (Rust toolchain)
```

For the Rust core and bindings:

```sh
cargo test -p wesc            # core unit/integration tests + doctests
cargo check -p wesc-go -p wesc-node -p wesc-py -p wesc_php
gofmt -l crates/wesc-go       # Go formatting (empty output = OK)
```

Note: the PHP crate's Cargo package name is `wesc_php` (underscore). The Go
and Ruby bindings build with their own toolchains (see each crate's README);
the Ruby binding requires Ruby headers (`rb-sys`) to compile.
